DATA PRIVACY & INVESTIGATIVE INTEGRITY

Privacy Architecture & Forensic Boundaries

Transparent documentation of how evidence is handled, processed, sanitized, and interpreted within PhotoTrace AI.

1. Local Server Evidence Handling
Strict Evidence Care

Ephemeral File Storage: When an image is uploaded for analysis, it is written to a private temporary file using a randomly generated UUID identifier. Once metadata extraction, hashing, and Error Level Analysis are complete, the temporary file on disk is immediately deleted.

Zero Public Directories: Uploaded evidence is never stored in a publicly accessible web folder or served as direct static assets to outside callers.

No Cloud AI Transmission: Photos are analyzed strictly on your local Flask host. They are never transmitted to OpenAI, Midjourney, Google Cloud Vision, or any remote generative AI provider without explicit user consent.

2. External Network Communications (Map Tiles & Geocoding)
Network Transparency

OpenStreetMap Tile Retrieval: When an uploaded photograph contains valid GPS coordinates, Leaflet requests map tiles from openstreetmap.org servers to display the location visually. No image bytes or file hashes are sent with these tile requests.

Approximate Reverse Geocoding: To provide human-readable landmark or city approximations, coordinates are queried via OpenStreetMap Nominatim with strict rate limits and caching. Results are explicitly labeled as approximate estimations.

3. Critical Investigative Boundaries & Limitations
Methodology Guidelines
Core Forensic Doctrine: A digital photograph file alone cannot establish legal author identity, who first transmitted it, or the originating messaging application without physical device inspection and corroborated chain-of-custody logs.

Non-Invention Rule: When an EXIF field or GPS coordinate is missing from an image file, PhotoTrace AI reports "Not available in this file". We never synthesize or guess missing telemetry.

Social Media Metadata Stripping: Most modern messaging platforms (WhatsApp, Telegram, Signal) and social networks (Instagram, Facebook, X/Twitter) automatically strip EXIF metadata to protect user privacy. Stripped metadata is completely normal for shared photos and is not standalone evidence of fraudulent tampering.

Software Modification Tags: When tags like "Adobe Photoshop" or "GIMP" are detected, it confirms the file was saved using that software. This may reflect innocent cropping, rotation, or batch compression rather than illicit manipulation.

Comparative Earliest Copy: When comparing multiple supplied files, the copy with the oldest recorded EXIF timestamp is designated the "Earliest supplied copy" within the provided dataset. It is never automatically certified as the original physical capture.

4. Hardened Security Safeguards
Defense in Depth
  • Magic Byte Verification: File headers are checked against true binary signatures, rejecting renamed executable or malicious scripts.
  • Decompression Bomb Protection: Pillow MAX_IMAGE_PIXELS is capped at 50 MP to neutralize pixel-flood memory exhaustion attacks.
  • Path Traversal Defense: All user-supplied filenames are sanitized via werkzeug.utils.secure_filename and stored exclusively under randomly generated UUIDs.
  • HTTP Security Headers: Responses enforce X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, and restricted Content-Security-Policies.
